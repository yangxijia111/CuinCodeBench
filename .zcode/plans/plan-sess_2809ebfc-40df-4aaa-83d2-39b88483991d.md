# CuinCodeBench v1.4.0 — Editor & Project Experience 实施计划

## 范围（推荐组合，批准时可调整）

1. **LSP 智能编辑**：诊断（squiggle）、补全、hover；pyright **内置打包**（纯 npm 包，开箱即用），clangd **检测 + 手工路径**（50MB+ 不内置），未装 clangd 时回退 **gcc/clang -fsyntax-only 解析诊断**（本项目主力工具链即 gcc，回退链覆盖面大）；pyright 缺失时回退 `py_compile` 语法检查。
2. **多文件项目**：题目附加文件（头文件/辅助源文件/数据文件）+ 文件 Tab UI + 多文件编译判题 + 提交快照。
3. **捎带技术债**：CPU 限频 `JOB_OBJECT_RATE_CONTROL`（设置项，**默认 0 = 不启用**，保证现有 TLE 语义与 CI 不变）。
4. 不做：minidump、备份增量、launcher 进程池（留后续版本）。

## 架构核心决策

**A. 每题工作区（LSP 与多文件的共同地基）**
- 位置：`{CCB_DATA_DIR}/workspaces/{problemId}/{language}/`，入口文件名沿用 `main.c|main.cpp|main.py`（RunPlan 不变），附加文件按相对路径存放。
- 工作区 = 编辑态真相：renderer 编辑防抖 250ms → IPC `workspace.sync` → main 写盘 + LSP didChange。**判题输入永远由 renderer 显式传入**（与现状 code 单字符串同语义，可审计、不读工作区，判题仍走临时目录复制即弃，v1.3 的隔离/清扫语义不变）。
- localStorage 草稿一次性迁移进工作区（读到工作区后删 key），消除双真相源。
- 备份不含工作区（编辑态可重建，语义与现状 localStorage 草稿一致，写入 Known Limitations）。

**B. LSP 客户端在 main 进程（LspService）**
- 每语言一个长驻 server：pyright（`process.execPath` + `ELECTRON_RUN_AS_NODE=1` + asarUnpack 的 langserver.index.js，pythonPath 用 ToolchainService 检测结果）；clangd（detect.ts 模式检测 PATH + 设置页手工路径）。**不进 Job Object**（长驻信任进程，与判题 Job 生命周期解耦），app 退出时统一树杀（复用 killAllActiveProcesses 模式）。
- 自研小 JSON-RPC stdio 编解码器（Content-Length 帧，参照 native-protocol.ts FrameDecoder 模式）；崩溃重启指数退避 ≤3 次后降级到诊断回退链。
- clangd 工作区生成 `compile_flags.txt`（与 buildRunPlan 的 `-std/-Wall` 对齐，保证诊断与判题编译一致）。
- LspService 不进 ServiceContext（同 ToolchainService 模式，避免备份换库 stale 引用）。

**C. IPC 新增事件通道（现纯 invoke 模型的扩展）**
- preload 新增白名单 `on('lsp.diagnostics', cb)`（返回退订函数，仅此一个事件通道，不暴露通用 on）；main 端推送目标限定 registerTrustedSender 注册过的窗口；事件 payload 走 shared 类型 + zod。
- 补全/hover 走 invoke 请求响应（`lsp.complete`/`lsp.hover`，本地往返目标 <100ms）。

**D. 多文件数据模型（migration v5，最小侵入）**
- 新表 `problem_files(id, problem_id, language, path, content, ord)`：附加文件；入口文件内容仍存 `problems.initial_code`（单一真相，内置 45 题种子零迁移）。
- `submissions` 加列 `files TEXT`（JSON 快照，可空；列新增对备份 v2 NDJSON 透明，旧备份导入天然兼容）。
- IPC：`judgeSubmit(problemId, language, code, files?)` / `runOnce` 同理。
- **安全约束**：path 白名单 `/^[A-Za-z0-9_\-./]+$/`、禁 `..`/绝对路径/盘符、深度≤8、≤16 文件、单文件≤100KB、总量≤1MB；编译在临时目录内，include 天然限于工作区文件。

**E. 多文件判题改造**
- `buildRunPlan` 接受文件集：gcc/clang 将目录内全部 `.c|*.cpp` 参与编译链接（入口 main 语义不变）；MSVC 同理；Python 附加 .py 同目录可 import；头文件不参与命令行。
- `writeSourceFile` → `writeWorkspaceFiles`（校验后写入）。
- CPU 限频：NativeLimits 加 `cpuRatePercent`，launcher 协议 **PROTOCOL_VERSION 升 2**（双端常量同步——memory 约束），C++ 侧 RATE_CONTROL 按设置启用；fallback 无此能力（文档注明 native-only，同内存/进程上限现状）。

**F. UI**
- PracticeView：有附加文件时显示文件 Tab 栏（单文件题目 UI 退化为现状，渐进披露）；LSP 可用性徽标；诊断/补全/hover 进 CodeEditor（开 autocompletion/foldGutter）；「重置」加确认并恢复 initial_code。
- ProblemEditView：附加文件管理（新增/删除/重命名）+ 编辑升级为 CodeMirror（现状是 textarea）。
- SettingsView：语言服务器区（检测状态、clangd 手工路径、CPU 限频设置）。

## 分期执行（P0–P9，每期可独立验证）

- **P0 设计文档 + 基线**：docs/V1_4_DESIGN.md（上述架构 + 安全 + 协议 v2）；跑全量门禁确认基线绿。
- **P1 PoC 三验证**：① pyright spawn+握手+收 publishDiagnostics；② clangd 同上 + compile_flags.txt 生效；③ CM6 linter/autocompletion/hover 扩展最小集成（vitest 内渲染诊断）。风险前置：打包态 ELECTRON_RUN_AS_NODE + asarUnpack 路径解析。
- **P2 IPC 事件基建**：preload on 白名单、可信窗口推送器、契约与单测。
- **P3 LSP 客户端**：JSON-RPC 编解码器、LspService（生命周期/退避重启/退出清理）、clangd 检测、pyright 内置路径解析、设置项。
- **P4 工作区服务**：WorkspaceService（open/sync/reset、path 校验、草稿迁移）+ IPC + 单测。
- **P5 编辑器集成**：CodeEditor 升级（诊断/补全/hover/折叠）、PracticeView 文件 Tab + 防抖同步 + LSP 徽标；UI 测试。stretch（尽力）：goto definition（跨文件跳 Tab）、LSP formatting、签名帮助——三者同走「LSP 方法转发」模式，边际成本低。
- **P6 多文件判题**：migration v5、problem-repository、schemas、buildRunPlan 多源、writeWorkspaceFiles、submissions.files 快照、judge-service 集成测试（util.h+util.cpp+main.cpp 全链路）。
- **P7 多文件 UI + 题目编辑器**：ProblemEditView 附加文件管理、备份表清单加 problem_files、DATA_SPEC.md 更新。
- **P8 CPU 限频**：launcher 协议 v2 双端、NativeLimits、设置项（默认 0）、native 测试 + 对拍回归。
- **P9 收尾**：E2E 扩展（多文件判题闭环含 DB 断言 files 快照；打包态 pyright 诊断端到端）、性能门槛（LSP 冷启动/诊断延迟/补全往返）、版本 1.4.0、Release smoke 断言 pyright 资产存在、V1_4_FINAL_REPORT.md。

## 测试策略（沿用现有模式）

- 纯函数单测：path 校验、buildRunPlan 多文件命令（含无 shell 元字符审计用例）、JSON-RPC 编解码、诊断映射（LSP→CM6）。
- 集成（skipIf 模式）：真实 LSP 会话（有 clangd/pyright 才跑）、gcc syntax-only 回退、judge-service 多文件全链路（:memory: 库）。
- native：协议 v2 字段透传 + 对拍更新；限频只断言配置生效与进程正常完成（不做时序脆弱断言）。
- E2E（CDP harness）：复用 replaceText 真实键盘注入。

## 验收标准

- 单文件题目全链路行为与 v1.3 完全一致（回归零变化）；CI（ubuntu/windows）、E2E 全绿。
- pyright 开箱：打包态安装后 Python 题目即有诊断+补全（E2E 证明）；clangd 未装时 C/C++ 有 gcc 回退诊断。
- 多文件题目（h+cpp+main）判题 AC 且 submissions 快照完整；`../` 等恶意 path 被拒（测试证明）。
- 默认设置下判题超时/资源语义与 v1.3 逐字段一致（对拍）；CPU 限频仅在显式开启后生效。
- lint/typecheck/unit（≥470 项目标）/E2E/build/dist 全绿；Release 资产含 launcher.exe 与 pyright。

## 已知约束（遵守 memory 记录）

- launcher 协议改动双端同步 version 常量 + native-protocol.ts；编译 /utf-8 + build-launcher.mjs。
- 新服务不闭包捕获初始 ctx，一律 getServices()。
- 「天」语义单源 LocalCalendarDay；SQL 禁 DATE('localtime')。
- 备份恢复后 LspService/WorkspaceService 不受换库影响（不依赖 DB 或走 getServices）。

## 需要的执行权限

npm 安装依赖（pyright）、运行 lint/typecheck/test/E2E、构建 launcher（cl.exe）、git 提交与打 tag、gh 触发 Release 验证。
