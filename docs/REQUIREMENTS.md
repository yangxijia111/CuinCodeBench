# REQUIREMENTS.md — 需求规格

术语：**FR**=功能需求，**NFR**=非功能需求。每条需求有唯一编号，供 ROADMAP 与测试追溯。

## 1. 功能需求

### 1.1 代码编辑（编辑器）

| 编号 | 需求 |
|---|---|
| FR-E1 | 支持 C、C++、Python 三种语言的代码编辑，切换语言保留各自草稿 |
| FR-E2 | 编辑器提供行号显示与基础语法高亮（按当前语言） |
| FR-E3 | Tab 键插入缩进（4 空格），支持自动缩进 |
| FR-E4 | 支持编辑器字号调整（设置页，范围 12–28px） |
| FR-E5 | 提供"重置代码"，一键恢复为题目初始代码（需确认） |
| FR-E6 | 草稿自动保存：编辑内容按 (题目, 语言) 保存在本地，切换题目/重启后恢复 |

### 1.2 本地 Runner

| 编号 | 需求 |
|---|---|
| FR-R1 | 自动探测本机 C/C++ 编译器：gcc、g++、clang、clang++、MSVC cl.exe（经 vswhere 定位 + vcvars64 环境解析） |
| FR-R2 | 自动探测 Python 解释器：`python`、`py`（经 `where` 定位 + `--version` 校验，排除 Microsoft Store 空壳别名） |
| FR-R3 | 所有子进程调用使用参数数组 spawn，**禁止 shell 拼接任何不可信内容** |
| FR-R4 | 每次运行/编译使用独立临时工作目录（系统临时目录下按运行 ID 隔离），结束后自动清理 |
| FR-R5 | 编译超时（默认 30s）与运行超时（按用例配置，默认 5s），超时强制终止整棵进程树 |
| FR-R6 | 捕获 stdout/stderr（UTF-8），每路输出上限 1MB，超限截断并标记 |
| FR-R7 | 记录 exit code 与终止信号 |
| FR-R8 | 编译错误完整展示（stderr 全文），运行时错误展示 stderr 与 exit code |
| FR-R9 | 系统缺少某语言工具链时，UI 明确提示该语言不可用及原因，应用不崩溃，其余语言可正常使用 |
| FR-R10 | 设置页支持手动指定工具链路径（覆盖自动探测），支持"重新检测" |

### 1.3 题库

| 编号 | 需求 |
|---|---|
| FR-P1 | 题目包含：标题、描述（Markdown）、难度（easy/medium/hard）、标签、输入说明、输出说明、示例（≥1）、初始代码（按语言）、测试用例列表 |
| FR-P2 | 测试用例包含：stdin、期望 stdout、超时（ms）、排序号 |
| FR-P3 | 支持新建、编辑、删除题目（内置题可删除，删除前确认） |
| FR-P4 | 支持按标题关键词搜索、按标签筛选、按难度筛选，可组合 |
| FR-P5 | 支持 JSON 导入（单题或题库数组，导入前校验格式）与导出（单题或全部） |
| FR-P6 | 首次启动自动灌入内置种子题库（≥8 题，覆盖三语言与三种难度），不重复灌入 |

### 1.4 自动判题

| 编号 | 需求 |
|---|---|
| FR-J1 | 逐用例执行：写入 stdin，捕获 stdout 与 expected 对比 |
| FR-J2 | 状态：Accepted / Wrong Answer / Compile Error / Runtime Error / Time Limit Exceeded；扩展：Output Limit Exceeded、Internal Error |
| FR-J3 | 结果展示：总用例数、通过数、每个用例的输入/期望输出/实际输出/耗时/状态 |
| FR-J4 | 输出归一化对比：统一 CRLF/LF、去除行尾空白、忽略末尾多余换行/空行（详见 ARCHITECTURE.md §5 判题策略） |
| FR-J5 | 顺序执行全部用例（失败不中断），总体状态取执行顺序中第一个非 AC 用例的状态 |
| FR-J6 | 编译失败时跳过所有用例，直接返回 Compile Error 并展示编译器输出 |

### 1.5 学习记录

| 编号 | 需求 |
|---|---|
| FR-H1 | 每次判题保存完整提交：题目、语言、代码、总体状态、通过数/总数、总耗时、时间戳 |
| FR-H2 | 保存每个用例的执行明细（状态、实际输出、stderr、exit code、耗时） |
| FR-H3 | 题目维度统计：尝试次数、首次通过时间 |
| FR-H4 | 提交历史可按题目查看，支持分页 |

### 1.6 错题系统

| 编号 | 需求 |
|---|---|
| FR-M1 | 判题失败自动记录错误（类型、摘要、语言、题目） |
| FR-M2 | 失败次数 ≥ 2 的题目自动进入错题列表；展示失败次数、最近失败时间、最近错误类型、各类型错误分布 |
| FR-M3 | 首次通过后错题仍保留（便于巩固），用户可"标记已掌握"移出列表，也可取消标记 |
| FR-M4 | 错题支持"重新练习"，直达该题练习页 |

### 1.7 Dashboard

| 编号 | 需求 |
|---|---|
| FR-D1 | 展示：总做题数（有提交的题目数）、Accepted 题目数、正确率（AC 提交/总提交）、今日提交数、连续练习天数 |
| FR-D2 | 展示 C/C++/Python 提交占比、常见错误类型 Top 5、最近练习记录（最近 10 条） |
| FR-D3 | 全部数据本地计算、本地保存 |

### 1.8 运行（自定义输入）

| 编号 | 需求 |
|---|---|
| FR-C1 | 练习页支持"运行"：以用户自定义 stdin 运行当前代码（不判题），展示 stdout/stderr/exit code/耗时 |

## 2. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 技术栈：Electron + React + TypeScript（strict），主进程/渲染进程职责清晰，经 IPC 通信 |
| NFR-2 | 本地存储使用 SQLite（better-sqlite3），数据存于系统用户数据目录；提供 `CCB_DATA_DIR` 环境变量覆盖（测试用） |
| NFR-3 | 数据访问层（repository）、业务层（service）、IPC 层、UI 层分离；核心逻辑不写入 React 组件 |
| NFR-4 | 单文件不超过约 400 行（数据模型/种子数据等声明式文件除外）；禁止巨型文件 |
| NFR-5 | lint（eslint）、typecheck（tsc --noEmit）、unit/integration test（vitest）、build 全部可一键执行并通过 |
| NFR-6 | 界面简洁现代，默认 Dark Mode，桌面端优先；左题目导航 / 中编辑器 / 右或下结果区 |
| NFR-7 | TS strict 模式；禁止 `any`（确需时用 `unknown` + 收窄）；禁止吞异常（捕获必须记录或上抛） |
| NFR-8 | 禁止写死绝对路径；临时路径、数据目录均由系统 API 或环境变量派生 |
| NFR-9 | 判题与运行在主进程串行队列执行（同一时间一个任务），避免资源竞争 |

## 3. Windows 兼容要求

| 编号 | 需求 |
|---|---|
| WIN-1 | 目标 Windows 10/11 x64；开发与验证环境为 Windows 11 |
| WIN-2 | 进程树终止使用 `taskkill /PID <pid> /T /F`（Windows 官方工具，参数为数组 spawn） |
| WIN-3 | MSVC 编译需先解析 vcvars64.bat 环境：启动 `cmd /d /s /c "...vcvars64.bat && set"` 捕获并解析环境差异，之后直接 spawn cl.exe（不再经过 shell） |
| WIN-4 | 文本编码：源码文件以 UTF-8（无 BOM）写入；程序输出按 UTF-8 解码；Python 判题运行时注入 `PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1` |
| WIN-5 | 文件/目录删除处理 Windows 文件锁：删除失败自动重试（延迟重试，最多 5 次） |
| WIN-6 | 路径含空格（如 Program Files）全程使用数组参数与显式 cwd，不依赖字符串拼接命令 |
| WIN-7 | 杀软/Defender 可能拦截新编译 exe：文档说明，不自动绕过 |

## 4. 安全边界

见 SECURITY.md。要点：本工具**不是安全沙箱**；只应运行自己或可信来源的代码；所有安全措施（超时、杀进程树、输出限制、临时目录、无 shell 拼接）目标是**稳定性与防失控**，而非防御恶意代码。
