# PRODUCT.md — 产品文档

## 1. 项目目标

CuinCodeBench 是一个**面向编程学习者的本地代码练习工具**：在本地桌面完成"读题 → 写代码 → 运行 → 自动判题 → 记录错题"的完整练习闭环，全程数据保存在本机，不依赖任何服务器。

一句话定位：**单机版轻量 OJ（Online Judge）+ 错题本 + 练习统计**。

## 2. 用户场景

- **场景 A（刷题练习）**：学习者打开题库，选择一道题（如"A+B 问题"），在内置编辑器中用 C/C++/Python 编写代码，点击"判题"，立即看到每个测试用例的通过情况、期望输出与实际输出差异。
- **场景 B（自由调试）**：学习者点击"运行"，用自定义输入快速验证代码行为，不必逐个跑测试用例。
- **场景 C（错题重练）**：某题连续多次判题失败后自动进入错题本；学习者从错题本进入"重新练习"，掌握后手动标记。
- **场景 D（回顾统计）**：学习者在 Dashboard 查看总做题数、正确率、连续练习天数、语言分布、常见错误类型，了解自己的练习状态。
- **场景 E（题库管理）**：教师/学习者自己录入题目（含测试用例），或通过 JSON 文件在同伴间分享题库。

## 3. 核心功能

| 模块 | 功能 |
|---|---|
| 代码编辑 | C / C++ / Python 编辑器，行号、基础语法高亮、Tab 缩进、字号调整、重置为初始代码、草稿自动保存 |
| 本地 Runner | 自动探测本机 gcc/g++/clang/clang++/MSVC cl.exe/python/py；编译+运行；编译/运行超时；进程树强制终止；输出捕获与大小限制；临时目录隔离与自动清理；缺编译器时 UI 明确提示 |
| 题库 | 内置种子题目；新建/编辑/删除/搜索/标签筛选/难度筛选；JSON 导入/导出 |
| 自动判题 | 逐用例执行（stdin → stdout 对比），输出 Accepted / Wrong Answer / Compile Error / Runtime Error / Time Limit Exceeded（扩展：Output Limit Exceeded）；展示总数、通过数、每用例输入/期望/实际/耗时 |
| 学习记录 | 全部提交历史（代码、语言、结果、用时、时间），首次通过时间，尝试次数 |
| 错题系统 | 自动聚合多次失败题目；错误次数、最近错误、常见错误类型；重新练习；标记已掌握 |
| Dashboard | 总做题数、Accepted 数、正确率、今日提交、连续练习天数、语言分布、常见错误类型、最近练习 |

## 4. 非目标（v1.0 明确不做）

- **不做安全沙箱**：用户代码以本机当前用户权限直接运行（详见 SECURITY.md），不适于运行恶意/不可信代码。
- **不做联网功能**：无在线题库、无账号、无云同步、无提交排行。
- **不做多语言 UI**：界面仅中文（代码与报错保持原样）。
- **不做复杂判题**：不支持 Special Judge、文件 IO 型题目、内存限制、多进程并发判题。
- **不做 macOS/Linux 适配**：仅面向 Windows 10/11（代码尽量跨平台，但不测试不承诺）。
- **不做移动端/响应式**：桌面端固定布局。

1. `npm install` 后 `npm run dev` 可正常启动应用；
2. C 与 Python Runner 在本机存在对应工具链时真实可运行（本机验证：MSVC cl.exe + Python 3.13 + 便携 MinGW gcc）；
3. 自动判题五种状态全部正确工作，输出归一化符合 ARCHITECTURE.md 判题策略；
4. 题库 CRUD、搜索、筛选、JSON 导入导出可用，内置种子题库首次启动自动灌入；
5. 提交历史、错题本、Dashboard 数据正确且持久化（SQLite）；
6. 无阻塞性 UI 缺陷（窗口、路由、编辑器、结果面板交互完整）；
7. `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build` 全部通过；
8. README 完整，docs/ 与实际实现一致；
9. 最终审计完成并产出 FINAL_REPORT.md，GitHub 打 tag `v1.0.0`。
